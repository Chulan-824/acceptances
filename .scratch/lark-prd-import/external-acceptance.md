# 真实环境验收交接

Status: ready-for-human

这是本地实现之外尚未取得的产品验收证据。当前没有已部署的 VPS、两台成员电脑或代表性真实 PRD，不把受控 Lark 子进程、回环 HTTP、静态检查或浏览器截图视作这些条件的替代证据。本次未部署或推送。

## 准备条件

- 单实例平台及真实 MySQL 已在目标 VPS 运行，具有 HTTPS 和团队入口限制；部署、数据迁移与备份另行授权。
- 两名成员分别登录平台 CLI，并在各自 OS 用户环境中通过 Lark CLI 1.0.98 完成个人授权。
- 专用测试 Campaign，以及至少一篇仅甲可读的测试 PRD；包含普通表格、复杂表格、图片、画板和不支持的嵌入内容样例。
- 成员目标 OS/架构清单。每个组合分别保存回执，不能从本机 macOS 推断其他系统。

当前 Unix 适配会取消 Lark 子进程组；非 Unix 适配仅由 Go 取消直接子进程，尚未提供进程树终止保证。若目标包含 Windows，需补齐该平台的子进程树取消，再取得对应实际 OS 回执，不能据本机结果宣称 Windows 导入和取消均已验收。

## 必须取得的结果

1. 两名成员各自启动 `acceptances lark connect --url https://平台域名`。网页只列本人的连接器；平台不主动连接成员电脑。
2. 甲在网页填 URL，使用自己本机的个人授权读取。乙的连接器不能领取甲的任务，乙在确认前不能读取任务或候选文件。
3. 甲预览标题、修订、正文、表格和图片，对照原文核对全文；分享锚点不会变成选区导入。评论不进入正文，缺口可见且需明确接受。
4. 甲确认共享后，乙可阅读平台快照。关闭甲的连接器或撤销原文访问后，已确认快照及图片仍可读。
5. 分别验证 Docx、Wiki→Docx、Wiki→Sheet 拒绝、权限拒绝、授权过期、电脑休眠/断网、限流、取消晚到和文档读取途中修改。
6. 重复导入、资源补全及双人并发确认符合合同，不重复造版本、不静默降级、不改变 Campaign 验收结论。
7. VPS 重启后历史快照、当前指针和作者不变；在独立环境恢复备份并核对正文、图片和引用完整性。

每轮回执记录实际版本、OS/架构、目标环境、脱敏步骤、结果和缺口，不归档 Lark token、认证 URL、密码或连接串。失败先定位本机个人授权、连接器到平台、平台保存或页面读取中的实际环节，不切换共享账号。
