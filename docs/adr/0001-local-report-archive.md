# 本地精简版以验证报告归档和人工反馈为核心

2026-10-09 确认。第一版面向个人本机 Docker 使用，由宿主机业务项目中的 Agent 执行验证，Acceptances 保存检查项、结果、证据和代码版本信息，并提供人工反馈及接受、拒绝。保留 Project → Campaign → Run，不再要求独立用例库、执行定义版本、跨轮覆盖合并或风险接受规则；失败结果也可保存，保存成功不代表人工接受。

不接对象存储，不提供用户认证、账号、会话或项目 token。一个 Project 可以关联多个本地目录，关联用于确定结果归属，容器不挂载业务仓库以执行测试。选择这一范围，是为了让创建项目和本地关联直接通向验证归档，避免当前候选版的身份初始化与完整验收门禁成为使用前提。

新版不兼容旧协议，不迁移旧数据，Docker 数据卷、CLI 与接入 skill 均按新版重新实现。执行阶段可重建确认属于本项目的旧 Docker 数据卷；这不授权删除业务仓库或其他项目的数据。本决策形成时尚未重建数据卷或修改运行实现；后续实现与验证状态见[实现交接](../v1-implementation-handoff.md)。

本决策替代 `.scratch/open-source-v1/` 中与上述范围冲突的旧决议，包括本机账号及 token、云存储和完整验收门禁要求。旧记录保留作历史依据，不能据此向新版重新添加已删除范围。

第二轮确认使用一份结构化报告及附件，包含需求标题与说明、验证时间、代码版本及未提交改动标记、验证环境，以及检查项的预期、实际结果和状态。版本或环境未知时明确标记，不阻止保存。每次实际验证新增 Run，可局部复验但不自动合并历史通过结果；人工决定绑定具体 Run，新增 Run 后需求显示待审，历史决定仍保留。

使用单个 Go 应用容器提供 API 和构建后的 Web，SQLite 保存记录，本地文件保存附件，统一放在一个持久数据卷。启动自动初始化及迁移，一条 Compose 命令启动，默认仅监听本机，移除 PostgreSQL 及其配置。此选择降低个人本机部署成本，不承担多实例服务或远程共享数据库需求。

用户在 Web 创建 Project，skill 在业务目录选择已有项目并建立宿主机关联；同仓库 worktree 共用关联，多仓库可归属同一 Project。CLI 随新版提供，skill 负责调用，日常使用不要求填写 UUID、token 或 Acceptances 源码路径。

第三轮确认报告及附件保存后不原地修改，文字错误通过补充说明纠正，整体有误则标记作废并说明原因；作废记录不能接受，重新实际验证才新增 Run，不引入 Report Revision。Web 支持删除 Project、Campaign 或 Run，确认时展示影响范围，并清理所属报告、附件与反馈；不做回收站、保留策略或自动历史清理。删除最新 Run 后需求回到待审，不自动恢复旧接受状态。

一次提交包含完整报告与附件，全部保存完成才展示。CLI 自动生成并保留提交 ID，同一 ID 和相同内容重复提交不新增记录，同一 ID 和不同内容返回冲突。失败后重传整包，不引入分片上传、断点续传或后台任务队列。
