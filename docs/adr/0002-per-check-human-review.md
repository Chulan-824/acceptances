# 以逐项人工评审作为整轮通过的依据

2026-10-11，用户确认每个 Check Item 都需要支持独立的人工通过、不通过和评论；一轮 Run 只有全部检查项均获人工通过，才满足整轮人工通过的条件。此目标将人工判断细化到具体检查项，解决现有整轮评论无法明确表达各项验收结果的问题。

这项变更重新界定 ADR-0001 中人工决定绑定 Run 的粒度，逐项人工评审仍归属于具体 Run。实现将人工决定绑定到本轮具体检查项，并自动计算 Run 状态，整轮仅保留评论。

第一轮确认的规则如下：

- 人工判断是人工验收的依据。Agent 的原始验证结果保留，验证失败的项目也可获人工通过，分别展示两种结论。
- 整轮人工状态自动计算，全部检查项均人工通过时整轮通过，无需再作一次整轮确认，也不能通过整轮接受操作绕过逐项人审。
- 评论与人工判断分开。添加评论本身不改变已有判断，发现问题时需要明确改判。
- 每轮独立人审，新 Run 不继承旧 Run 的人工判断。局部复验通过仅代表本轮覆盖范围，不跨轮汇总成需求整体通过。

第二轮确认的规则如下：

- 检查项允许改判为通过、不通过，或撤回到待审。每次操作保留历史，以最新明确判断为准，并立即重新计算整轮状态。
- 人工不通过必须填写理由。Agent 结果为失败、阻塞或未执行时，人工通过也必须填写理由；其余正常通过的理由可选。
- 保留整轮评论，用于整体情况和没有对应检查项的新问题。评论不改变原 Run 的人工状态，Agent 处理新问题后在下一轮增加对应检查项。
- 已有报告和旧整轮评审作为历史保留，不将旧整轮接受推断成逐项通过。已有检查项从待审开始，按新规则重新计算；作废记录继续作废。

第三轮确认的规则如下：

- 作废状态优先；任一检查项人工不通过时整轮不通过；没有不通过但仍有待审项时整轮待审；全部人工通过时整轮通过。
- 报告明确区分完整验证、局部验证和范围未知。局部 Run 人工通过只改变本轮状态，Campaign 仍待审；只有最新的完整验证 Run 全部人工通过，Campaign 才整体通过。
- 新 Run 结构化关联来源 Run、所处理的反馈和逐条处理说明，未处理或受阻也如实说明。关联不继承人工判断，不自动关闭人工评审。
