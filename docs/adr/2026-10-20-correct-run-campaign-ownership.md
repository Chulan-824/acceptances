# 更正 Run 需求归属，保留原验证身份

2026-10-20，用户明确要求把误归入 6.3、6.5 需求的当前 6.4 Run 及全部附件迁至独立 6.4 Campaign，保留原验证时间、结果及记录，不新建验证轮次，也不影响原历史交付。

在 ADR-0001 的报告与证据不可原地改写边界上，新增独立的需求归属更正能力：同一 Project 内调整 Run 的 campaign_id，事务中追加带理由和幂等请求 ID 的迁移记录，并重算两边最新轮次及需求状态。原报告、提交摘要、保存时间、人审及附件保持不变。Web 展示迁移记录，CLI/API 提供迁移入口。

已被任何交付快照引用的 Run 禁止迁移，避免改变历史交付与来源归属；单条迁移也禁止拆分反馈复验链。其他 Run 的历史交付、效力事件和文档完全不变。迁移不是人审或重新验证，不合并旧检查结果。

保留原附件中的 Campaign ID，通过独立、连续的迁移链验证正式交付材料的最初归属。冻结仍绑定当前需求、完整 Run 及当时人审；旧确认 token 失效，原字节与 SHA-256 不变。代价是原报告叙述可能含原归属，由独立迁移记录解释，而不是重写验证事实。协议和恢复边界见 [Run 迁移](../../contracts/run-moves.md)。
