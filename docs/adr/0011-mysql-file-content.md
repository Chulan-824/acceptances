# MySQL 保存完整文件内容

2026-10-24，用户批准将现有全部文件迁入本地 Docker MySQL，完成表结构、读写改造、全量迁移和真实接口与页面验证。保留原 SQLite、附件目录与备份，不提交代码。

本决策替代 ADR-0010 中本地附件是权威存储的部分。业务表、UUID、冻结快照原文、历史时间、人审和删除保留规则不变。已有 MySQL 是权威业务数据源，禁止从已落后的 SQLite 重新覆盖。

文件模块统一负责写入、封存、引用、分块读取及迁移。调用方通过文件集合接口读取；旧目录适配器仅服务兼容和导入。MySQL 使用完整 SHA-256 去重的对象、1 MiB 分块及独立的 Run/Delivery/Document 引用，冻结后不再复制字节。发布引用与业务记录在同一个事务，封存内容与冻结引用由触发器和外键保护。读取持有一致快照，兼容 HEAD/Range 和视频拖动。

全新空 MySQL 直接启用数据库文件后端。旧归档保持原后端，停写、完整备份、声明与磁盘集合核对、全部写入和数据库完整回读、源文件与 11 张业务表摘要复核后，原子激活数据库后端。迁移可重试，差异拒绝覆盖。提交不确定时保留对象，不自动回收、不回退文件系统。

完整 MySQL 备份包含文件，允许空本地目录恢复启动。旧源和备份保留，历史 SQLite 不再同步。后续清理必须单独授权并提供可验证的恢复方案。当前不引入对象存储、文件系统写缓存或多实例写入。

表结构、命令与验证边界见 [MySQL 存储](../mysql-storage.md)。本决策不代替实际迁移回执。
