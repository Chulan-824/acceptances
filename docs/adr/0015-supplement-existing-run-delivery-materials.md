# 既有验证可追加来源和交付资料，验证事实与人审保持不变

2026-10-28，用户明确要求为已完成的测试环境验证补齐源码版本和正式交付材料，不重复验证、不新建 Run，保留原验证结果、证据和人工验收。该决定调整 ADR-0001 的“发布后不能补资料”和 ADR-0005 中将未知版本直接等同于需要重新验证的流程要求。

资料补充独立追加保存，记录操作者、时间、理由、原版本、新版本、附件摘要与检查项附件关联。原始 report、提交摘要、验证时间、范围、检查项预期/实际/结果、原附件、评审及反馈记录不改写。Run 的读取和交付准备使用补充后的版本与附件，同时展示补充历史；发布重试继续核对原提交摘要。补充本身不构成一次验证，不创建 Run，也不自动产生人工判断。

补充者须确认材料属于该次已完成验证，并提供版本归属或补充依据。版本补录是有来源的事后确认，不表述为原执行器已记录的信息；源码或构建确实发生变化时，不能靠补充资料将旧验证宣称为新版本验证。正式冻结仍要求明确的源码、构建绑定、完整地图与材料摘要。

附件只新增，原文件名不能覆盖；新附件可关联既有检查项，不能新增或改写检查结果。补充使用最新准备 token 防止陈旧提交，同 requestId 同内容幂等，异内容冲突。MySQL 文件引用与补充记录在同一事务提交，失败不对外展示新增文件。已作废、合并归档或曾冻结的 Run 不允许补充，冻结快照和说明保持不可变。

交付地图的 check ID 接受 ASCII 大小写字母，按原值匹配，兼容既有 Run 的 T06 等稳定标识；不能为满足地图格式而改写原检查项或大小写。功能 ID 仍使用小写规则。

项目侧使用 CLI `preparation` 和 `supplement`，Web 展示补充后的资料及审计记录。是否正式冻结与异常接受理由仍由用户确认；不因补资料重新要求人工评审或重置已有判断。
