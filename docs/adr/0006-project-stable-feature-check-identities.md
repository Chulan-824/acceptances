# 功能与检查项的身份在项目内长期稳定

2026-10-13，用户确认 featureId 与 checkId 在同一 Project 内唯一、稳定，同一功能或检查行为跨 Campaign、Run 复用，单纯改名不换 ID。选择项目范围而非单次需求范围，是为了让后续地图、证据和业务说明可以长期对应同一行为。

稳定身份由业务项目侧维护，不因此新增独立用例库。Run 仍只保存当次验证事实，每轮独立人审；复用 ID 不继承历史人工结论，也不合并跨轮验证结果。现有 report 不直接添加未知字段，地图及素材如何表达身份关系继续对齐。

用户进一步确认，检查预期发生实质变化时新建 checkId，旧 ID 保留原含义；单纯改名、排版或不改变预期含义的文字澄清仍沿用原 ID。这让同一个检查 ID 始终对应同一行为要求，是否属于实质变化由项目侧根据需求判断，平台不自动推断自然语言含义。

功能拆分或合并、ID 命名及废弃规则仍在[规划草稿](../../.scratch/delivery-snapshot-business-doc/spec.md)中待定。这份决策尚未实施。
