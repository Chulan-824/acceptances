# 将早期验证合并留档到当前完整报告

## 背景

6.4 因交付材料格式问题先后形成两份同范围、同结果的完整验证记录。用户要求在独立需求中合成一轮，同时保留原验证时间、结果、记录与全部附件。

## 决策

将后一份独立完整验证作为当前报告；以不可变归档关系把早期 Run 归入当前报告。原 Run ID、报告字节、附件和评审都不改写。若跨需求，迁移与合并关系在同一个事务内保存，采用请求 ID 保证重试幂等。需求列表只列独立报告，原报告入口只读，主报告内折叠提供早期记录与附件入口。

只接受同版本、同环境、同完整范围且逐项预期和结果一致的两份报告。主报告仍单独满足交付范围，人审不转移、结果不拼接。历史交付引用与反馈链禁止合并；禁止嵌套、循环和独立拆散归档。

## 取舍与后果

数据库仍保存两次实际验证，但产品以一轮当前验收呈现，历史明确标注原验证时间。不能把此功能用于凑齐跨轮通过结果。schema v6 自动一致备份；新增归档字段影响主报告的冻结确认摘要，旧确认令牌失效。新交付仍仅使用主报告证据；早期错误不被修正或覆盖。
