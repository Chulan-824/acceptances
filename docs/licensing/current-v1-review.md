## 实际交付内容

- 源码仓库：根 LICENSE、LICENSE-SCOPE、NOTICE、LICENSES 和 docs/licensing 一起提供；`.scratch/` 继续忽略。公开完整历史与仅发布某个源码快照是不同的审查范围，不能混为一谈。
- Go 服务：本地 `build/server` 的构建信息为上述 HEAD、go1.26.8、darwin/arm64，含 10 个第三方模块，与 go.mod 一致。`build/acceptances` 同基线，仅 Go 标准库，无第三方 Go 模块。此证据不是 Linux Docker 镜像的二进制证明。
- Web：锁定 React/React DOM 19.2.8、scheduler 0.27.0；现有 bundle 含 Vite modulepreload helper，因此也随附 Vite 8.2.2 原许可。构建工具不能一概从运行归属中排除。
- Docker：最终层为固定 digest 的 Debian bookworm-slim，复制两个 Go 程序、Web 和 Go 构建层的 CA bundle。现在构建配方也复制完整许可目录到 `/app/licensing`。Debian 包条款、对应源码提供义务及 CA 材料仍须按实际镜像核查；Node/Go 构建镜像不是最终镜像的整层内容。PostgreSQL 已不在当前配方。
- 安装 skill：安装器在 skill 的 `licensing/` 保留相同结构与原文，并输出路径。`bin/acceptances` 的独立拷贝应连同该目录分发；单独拷贝裸二进制不能沿用“已随附材料”的结论。直接拷贝源码 skill 两个文件也不包含许可包。
- 旧的 `build/`、Web dist、已安装 skill 或已运行容器不会因修改配方自动补齐许可。正式候选须重新构建并检查文件与摘要。
