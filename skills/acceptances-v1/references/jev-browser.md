# 可选 Jev 执行

Jev 辅助 Agent 操作本机真实 Chrome，验证结果仍由 Agent 核对并归档。它使用执行者自己的 TypeSafe Key；部署 Acceptances 服务不会向其他人提供部署者的 Key。没有 Jev 时继续原有验证、反馈复验和发布流程，保持同一 Campaign 和本次范围。

## 探测与选择

先确定本次允许使用的真实浏览器工具和待测 URL。用户明确禁用 Jev、只允许某个工具或不允许页面内容发送到 TypeSafe 时，直接使用原工具。其他浏览器验证先执行一次以下探测，路径替换为当前加载的 skill 目录：

```sh
python3 /绝对路径/acceptances-v1/scripts/jev-probe.py --url http://127.0.0.1:5173/
```

探测仅运行 Jev 的 `doctor`，不连接 Chrome、不调用模型、不修改数据，也不安装依赖。输出 `executor`、`reason` 和可定位时的 `root`；正常选择退出码为 0，包括回退选择。`executor=jev` 只表示配置及依赖检查通过，`browser_checked` 和 `model_checked` 仍为 false，Key 有效性及 Chrome 连接需要后续实际执行确认。

执行器按以下顺序定位：环境变量 `ACCEPTANCES_JEV_ROOT` 指定的 Acceptances 源码目录、当前 skill 所属的源码目录、安装时记录的源码路径。显式路径失效时直接回退，不猜测其他机器路径。安装路径记录在 `scripts/jev-runtime.json`，只含源码目录，不复制 Key、私有环境文件或虚拟环境。迁移机器后，可用 `ACCEPTANCES_JEV_ROOT` 指向该机器已有的源码目录；未配置执行器不影响 CLI 使用。

遇到 Python 不可用、脚本缺失、执行器路径失效、缺 Key、依赖不足、配置错误或探测超时，记录原因并立即使用原工具，不要求用户先安装 Jev。探测当前仅支持宿主机执行器；用户已选择 Docker 执行器时，在已知源码目录按项目接入文档运行 `make jev-docker-doctor`，采用相同的回退规则，不自动构建镜像。

当前 Jev 只支持无凭据的本机 HTTP URL。HTTPS、远程域名等交给原工具验证，不通过更改目标 URL 绕过限制。原工具沿用业务仓库规则、现有登录状态和授权范围；未指定时选择当前可用的真实浏览器工具。工具仍不可用则报告阻塞，Playwright 脚本须有单独的明确授权。

## 执行

探测选中 Jev 后，读取返回 `root` 下的 `docs/agents/jev-browser.md`，遵循其任务合同。在该源码目录调用已有启动器；待测地址仍是业务应用地址，不能替换成 Acceptances 归档服务的地址：

```sh
make -C /探测返回的源码目录 jev-inspect URL=http://127.0.0.1:5173/
make -C /探测返回的源码目录 jev-run TASK=/绝对路径/task.json
```

启动器加载执行者本机配置并注入子进程，Agent 不读取或打印 `.env*`，不向用户索要聊天中的 Key。配置存在表示按本流程尝试调用官方 Jev API，页面 URL、可见内容和任务输入会发往 TypeSafe；沿用用户和业务项目的数据使用限制。

先用 `inspect` 取得实际页面及完整控件标签，再编写任务。填表值必须明确，任务必须包含与本次检查对应的 `expect` 断言；列表入口另写 `ready`，使用已知行名、总数等数据就绪条件。使用导航/登录/数据阶段时限（默认 30/15/30 秒）及总时限，读取 `timings` 定位等待，不通过无限重试拖长回归。截图直接保存 JPEG（.jpg），其他浏览器续验截图也先编码为 JPEG 再入包。写操作遵守业务授权，使用专用合成数据；检查原有 Run 时默认只读，人工评审仍由用户完成。

读取实际退出码、`result.json` 和截图。`verified` 仅覆盖任务中的 URL/文字断言；持久化、权限等业务结论按需要补充页面及 API 检查。`DONE`、`claimed_done` 或动作已发出均不能单独标记通过。

## 回退与续验

| 情况                                        | 行为                                                                     |
| ------------------------------------------- | ------------------------------------------------------------------------ |
| 缺配置、依赖或执行器，Chrome 启动前连接失败 | 记录原因，用原工具执行本次检查                                           |
| Key 无效、额度不足、模型服务或网络不可用    | 保留 Jev 证据，核对已执行动作后用原工具续验                              |
| 页面无进展、缺少明确输入或达到预算          | 观察当前状态，由原工具继续尚未完成的范围                                 |
| 业务断言不成立                              | 保留该次失败及证据，排查实际状态；不能将其改写为工具不可用或因回退而删除 |
| 动作结果未知、用户中断或涉及授权边界        | 停止自动重放；只读核对状态。用户中断结束本次执行，授权不足的部分报告阻塞 |

回退前读取动作记录。`dispatching` 表示结果不确定，`executed` 表示已发出；两者都须核对页面和业务状态，避免重复提交。仅明确未执行且仍在授权范围内的步骤可以继续。原工具也不可用时如实保存阻塞，其他可验证内容继续执行。

在报告现有的 `environment`、`description` 和检查项 `actual` 中记录实际工具、回退原因、Jev 与续验分别覆盖的内容；在 `evidence` 中附真实截图及必要的执行记录。使用平铺且唯一的附件名，按业务规则处理敏感信息。无需给 `report.json` 添加新字段。完成实际复验后发布新的 Run 并保留来源反馈关联，旧 Run 和人工判断保持不变。
