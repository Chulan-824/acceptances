确定性证据优先 (Evidence-First)

测试不仅是单一的 Pass/Fail 计数，更内嵌高分辨率实测截图、网络 HAR 抓包与控制台日志，杜绝“在我机器上是好的”口头扯皮。

✓ 自动化高分截图留底
✓ HAR 链路与异常日志追踪

双层核验与责任签署

机器验证客观事实写入 result.json；人工业务审阅写入 reviews.json，分权明确、责任闭环。

✓ 机器归机器，人工归人工
✓ 签署时间戳与责任人存证

三步完成可审计的交付闭环

简单直接的命令行操作与直观的本地可视化，契合开发者日常编码节奏。

1

自动化执行与证据捕获

开发者完成特性编码后，运行自动化验收脚本。脚本驱动真实本地服务，产出用例检查数据与高清截图存入对应特性 Round 目录。

$ npm run accept:check
2

启动查看器可视化核验

运行一行 CLI 快速调起本地优先的 Acceptances 查看器。三栏式直观对照用例预期、观察事实与截图证据，或在研发中枢全局巡检。

$ npx acceptances open
3

人工验收签署并入库封存

QA 或研发负责人在界面中一键签署「交付接受」，签署人姓名与意见实时落盘至 reviews.json，随代码一同 Commit。

$ git add .acceptances && git commit

透明开放的原位目录规范

完全基于文件系统约定，没有任何私有二进制黑盒，随处可读、永久归档。

为什么选择 Acceptances？

对比传统口头交付与重型云端测试管理系统。

评估维度 传统群聊 / 口头交付 Acceptances (本地优先)
证据沉淀 群聊聊天记录易过期丢失 代码库同源版本化管理，永久留存
多轮历史 改动后难以与上一轮截图对比 Round 历史清晰可回溯，Diff 一目了然
责任确认 缺乏正式签名，出了问题互相推诿 reviews.json 责任人签字盖章存证
环境成本 搭建重型云端系统，网络卡顿繁琐 0 依赖极速启动，开箱即用
