# 验证报告合并归档

POST `/api/v1/runs/{primaryId}/consolidate`，输入 `{requestId,sourceRunId,fromCampaignId,reason}`。首次 201、相同请求重试 200；相同请求 ID 的不同参数 409。

将早期验证归入较晚的完整报告，两份不可变 Run 均保留。归档关系单独追加；如果需求不同，在同一事务中迁移早期 Run。默认需求列表不将早期记录计为独立轮次，`?includeArchived=true` 可读取完整历史。当前 Run 返回 `consolidatedRuns`，早期记录返回 `consolidatedInto`；原始附件仍通过原 Run ID 读取。当前验证结果、人审判断及正式交付材料仅来自当前 Run，不拼接或继承早期结果，不新建 Run。

要求同项目、同源码版本、完整范围、环境与范围一致，检查项 ID/预期/结果完全相同，当前报告发布时间及验证时间不早于来源。禁止作废记录、已绑定任何交付快照、反馈链、嵌套归档或循环。被合并的早期记录只读，不允许新增评审、作废、独立迁移或删除；主报告也不能独立迁移或删除，以免拆散归档。需求/项目整体删除仍遵循既有明确删除流程。关系不可原地更新。

schema v6 升级前创建一致 SQLite 备份。所有报告 JSON、submission/hash、原始验证和保存时间、附件、既有评审及历史交付保持不变。合并主报告以后冻结时仍只冻结本次真实验证的材料，早期记录不成为本次通过依据。
